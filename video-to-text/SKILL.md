# video-to-text

把本地视频转成结构化的中文文字报告。**只接本地文件路径，不做下载**。

## 适用场景

- ✅ 单人独白视频（vlog、口播、教程）
- ✅ 双人对话视频（访谈、播客、对谈）
- ❌ 3 人及以上场景——拒绝，告诉用户超出 skill 设计范围

## 核心使用原则

1. **中文必须显式 `--language zh`**——whisper 自动检测会把中文识别成日语
2. **优先 large-v3 模型，不用 turbo**——内容研究质量优先，多等几分钟值
3. **最终只留 md，不留 srt**——srt 是中间产物，md 报告里要把分段全文 + 时间戳完整保留，承担"回查原文"的作用。md 生成成功后删 srt
4. **3 人以上场景明确拒绝**——不糊弄，给替代方案

## 工作流程

### Phase 1：接收输入 + 场景确认

问用户两件事：
- **视频文件路径**（绝对路径，可拖文件到终端获取）
- **场景**：单人独白 / 双人对话

验证：
- 文件存在性：`test -f "<path>"`
- 文件格式被 ffmpeg 支持：`ffprobe "<path>"`
- 如果是 3 人以上场景，拒绝并提示：

  > 这个 skill 设计用于单人或双人。3 人以上的角色分离需要专业工具（pyannote.audio / WhisperX）。建议你单独处理。

### Phase 2：确定输出位置 + 转录

询问输出位置（不预设默认值）：

> 转录文件存到哪？常见选项：
> 1. 视频同级目录（默认推荐）
> 2. ~/Documents/视频转录/
> 3. 你指定的其他路径

跑命令（srt 是中间产物，后面会删）：

```bash
mlx_whisper "<video_path>" \
  --model mlx-community/whisper-large-v3-mlx \
  --language zh \
  --output-format srt \
  --output-dir "<output_dir>"
```

**提示用户**：首次运行会从 HuggingFace 下载 ~3GB 模型（2-5 分钟）。后续运行模型已缓存。转录速度约为实时音频的 10-15 倍。

### Phase 3：Claude 处理 srt

读取生成的 srt 文件，做三件事：

1. **语义分段**——按话题转换分段，不是按时间硬切。每段标注 `[起始-结束]` 时间戳 + 一句话主题。
2. **角色推断**（仅双人场景）：
   - 看问答模式（"你觉得…"→ 提问者；"我认为…"→ 回答者）
   - 看说话口吻和身份线索（主播 vs 嘉宾、采访者 vs 被采访者）
   - 推不出来就老实标 `SPEAKER_A` / `SPEAKER_B`，**不要瞎猜**
3. **核心观点总结**——3-5 条要点，必须是原视频里的实质观点，不是套话。

### Phase 4：输出 markdown 报告 + 清理 srt

按下方模板生成报告，存到用户指定位置。文件名：`<视频文件名>.transcript.md`。

**md 写入成功后立即删 srt**：

```bash
rm "<output_dir>/<视频文件名>.srt"
```

注意：**只有 md 文件确实写入成功**才能删 srt。如果 md 生成中途出错，保留 srt 让用户能重试。

输出完成后告诉用户：
- 报告路径
- 后续可串接的 skill 建议

## 输出模板

```markdown
# 视频转录报告：<文件名>

**时长**：<MM:SS>
**场景**：<单人独白 / 双人对话>
**原视频**：<原始视频路径>
**生成时间**：<YYYY-MM-DD HH:MM>

---

## 核心观点

1. <要点 1>
2. <要点 2>
3. <要点 3>

## 金句摘录

> "<原话 1>" — <角色或时间戳>
> "<原话 2>" — <角色或时间戳>

## 分段全文

### [00:00-02:15] <段落一句话主题>

**角色 A**：<对话内容>

**角色 B**：<对话内容>

### [02:15-05:30] <段落一句话主题>

**角色 A**：<对话内容>

...
```

单人场景时省略 `**角色 A/B**` 标记，直接段落正文。

## 错误处理

| 情况 | 处理 |
|------|------|
| 视频文件不存在 | 让用户重新提供路径，不要瞎猜 |
| 文件格式不被 ffmpeg 支持 | 提示先转码：`ffmpeg -i input.xxx -c:a aac output.mp4` |
| mlx_whisper 未安装 | 提示安装：`uv tool install --python 3.12 mlx-whisper` |
| HuggingFace 下载失败 | 检查网络；提示用 `HF_ENDPOINT=https://hf-mirror.com` 走镜像 |
| srt 解析失败 / 内容明显错乱 | 报错，**保留 srt** 让用户能看原文，**不要硬总结也不要删 srt** |
| 3 人以上场景 | 拒绝并给替代方案（WhisperX / pyannote） |

## 绝对不要做的事

- ❌ 不要在没看到视频路径前就开始跑命令
- ❌ 不要伪造角色标注——内容判断不出就老实标 SPEAKER_A/B
- ❌ 不要省略时间戳——内容研究需要能定位到原视频片段
- ❌ 不要在 srt 解析失败 / md 没写成功时删 srt——只有 md 落盘成功才能删
- ❌ md 报告里的「分段全文」不能省略——它代替 srt 承担"完整原文"的角色
- ❌ 不要自动联动 /download-video——本 skill 只处理本地文件
- ❌ 不要用 turbo 模型——质量优先于速度
- ❌ 不要省略 `--language zh`——会被识别成日语

## 后续建议（条件触发）

| 触发条件 | 推荐 |
|---------|------|
| 用户做对标研究 | 「转完了，要不要接 `/dbs-benchmark` 做对标分析？」 |
| 用户在做内容创作 | 「转完了，可以用 `/dbs-content` 拆解这个视频的内容结构」 |
| 用户在拆解概念 | 「这段话里有几个值得拆的概念，要不要用 `/dbs-deconstruct`？」 |
| 转录质量明显有问题 | 「这段识别错误率偏高，建议加 `initial_prompt` 提示词重跑（md 里的『分段全文』已是当前能拿到的最完整原文）」 |

## 说话风格

1. **直接执行，不啰嗦**——确认路径和场景后立刻跑命令，不要反复解释
2. **遇到错误说人话**——不要把 stderr 原样甩给用户，要翻译成可操作的建议
3. **总结要有实质**——3-5 条核心观点必须能让用户看完后跳过原视频，否则就是失败

## 语言

- 用户用中文就用中文回复，用英文就用英文回复
- 中文回复遵循《中文文案排版指北》
