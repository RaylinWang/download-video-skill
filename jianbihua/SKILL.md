# /简笔画 — Raylin 风格简笔画配图

## 核心定位

把教学内容、口播稿、图文笔记里的关键概念、流程、结构、状态或隐喻，画成一张清爽、认真、轻微荒诞的手绘简笔画解释图。

目标是图解概念结构（谁给谁 / 流程 / 对比），让零基础的人一眼看懂。纯装饰贴纸、商业插画、PPT 信息图都算跑偏。

固定视觉 IP 是 Raylin 的手绘 Q 版角色：长深色头发 + 碎刘海 + 粉色挑染、大眼睛、浅蓝 T 恤、亲和元气。**标准形象以 `assets/character-ref.png` 为准，带角色的生图默认使用参考图。**角色必须承担画面的核心动作，只站旁边看就算失败。

## P0 规则

每次调用本 skill 都必须调用生图模型/图像生成工具产出核心视觉结果。不要只写 prompt、不要用 SVG 顶替、不要只用 HTML/CSS 或脚本画一个本地占位图交付。

在 Codex 里优先使用内置图像生成能力（`gpt-image-2` / image generation tool）。如果当前工具支持参考图，必须附带 `assets/character-ref.png`；如果当前工具不支持上传参考图，就把 `character-ip.md` 里的角色固定特征写进 prompt，并在生成后严格检查是否跑模。

如果当前环境没有可用生图模型，直接说明被阻塞，因为这个 skill 的交付依赖生图。

## 先读这些参考

按任务需要读取，不要一次塞满上下文：

- `references/style-dna.md`：风格 DNA、颜色语义、禁忌。
- `references/character-ip.md`：角色外形、气质、动作库和禁忌。
- `references/composition-patterns.md`：结构类型、原创隐喻方法和反复刻规则。
- `references/prompt-template.md`：生图提示词模板（三画幅变体）+ 编辑提示词。
- `references/qa-checklist.md`：生成后检查和迭代规则。

## 工作流

### 1. 定画幅

按输入类型选，用户明确指定时以用户为准：

| 输入 | 画幅 | 用途 |
|------|------|------|
| 口播稿 / 教学 PPT 内容 | 16:9 横版（默认） | 录屏演示、拍摄包插图 |
| 小红书图文笔记正文 | 3:4 竖版 | 图文笔记配图 |
| "画一个 XX" 单物件/单角色需求 | 贴图模式 | 封面元素、视频贴纸，白底居中大留白便于抠图 |

16:9 教学插图额外注意：插图会和文字块并排出现在 PPT / 拍摄包里，构图要撑得起和文字块相当的画幅，不要缩在角落。

### 2. 消化内容

读用户给的口播稿、笔记、大纲或概念。提炼：

- 核心观点是什么
- 哪些地方承担认知转折
- 哪些内容适合用图解释，哪些只适合文字

不要平均配图。优先选认知锚点：核心判断、前后对比、输入输出、分流、踩坑、状态变化。

### 3. 出 shot list 或直接生成

- **1-2 张**：直接进入生成。
- **3 张及以上**：先出 shot list 给用户审，确认后再批量生成。每张写清楚：放在哪段后、主题、核心意思、结构类型、角色在做什么、建议中文标注词。

隐喻必须从当前内容现场原创，禁止复刻过往案例构图（规则见 `composition-patterns.md`）。

### 4. 单张生成

每张单独生成，不要多张拼一张。提示词按 `prompt-template.md` 组装，发给图像模型的 prompt 用英文，图上标注文字用中文。

**默认路径：Codex 内置生图**

1. 使用 Codex 当前可用的图像生成工具生成图片。
2. **带角色的图：优先附带 `assets/character-ref.png` 参考图**（迭代改图时改传上一版图片）。如果工具接口不能上传图片，把角色固定特征完整写进 prompt。
3. 每张图单独调用一次生图，不要多张拼一张。
4. 生成后对照 `references/qa-checklist.md` 检查角色一致性、结构表达和文字可读性。

**备用路径：Dia 浏览器调 ChatGPT 出图**

当 Codex 生图不可用、但用户允许走浏览器时，再使用 Dia/ChatGPT 路径。带角色的图同样必须上传 `assets/character-ref.png` 参考图。

**只出 prompt 的边界**

只有用户明确说"只要 prompt"时，才可以只输出 prompt。其他情况下，本 skill 必须实际调用生图模型。

### 5. 检查与迭代

生成后对照 `references/qa-checklist.md` 逐项检查。常见失败优先重生成或局部编辑：

- 粉色跑出头发，扩散到批注或物件
- 角色画成网红脸 / 美少女 / 幼儿卡通
- 角色只是装饰，去掉后图仍然成立
- 画面太满、太像 PPT 或说明书
- 中文错字严重

### 6. 保存交付

存图路径优先级：

1. 用户指定的路径
2. 正在做某条内容时：`~/Desktop/内容创作/3-内容创作/{分类}/{DayXX-标题}/拍摄包/插图/`
3. 都没有：`~/Downloads/`，并告知用户

按顺序命名：`01-主题.png`、`02-主题.png`。不覆盖已有文件。

## 输出口径

生成前的策略输出短而准。生成后交付：生成了几张、每张用途、保存路径、哪张最稳哪张建议重生。不要长篇解释风格理论。

## 语言

- 跟用户沟通用中文
- 发给图像模型的 prompt 用英文
- 图上标注文字用中文
